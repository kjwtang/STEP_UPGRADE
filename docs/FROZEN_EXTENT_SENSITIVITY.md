# Frozen identities: 0.5 / 0.1-mm/h rain extent sensitivity

This is an experimental **measurement layer**, not a new storm classifier or
tracking preset. Scientific motivation and distinctions are recorded in
[the definitions review](STORM_DEFINITIONS_REVIEW_2026-10-02.md). Keep the frozen
1-mm/h graph and its original branch/event convention unchanged.

## What is compared

Both extents use exactly the saved A_1mm seeds from
[the paired threshold experiment](RAIN_THRESHOLD_SENSITIVITY.md). Seeds are
reidentified from the checksummed hourly rate cube and compared with every saved
seed raster hash. Saved timestamps, grid, units, catalog IDs and seed areas
must agree. The original graph, checkpoints, branch IDs and event files remain
read-only; their file hashes are recorded and rechecked. No tracking function is
called and no new graph is emitted. Referencing the graph is not a fresh tracker
replay or new independent evidence of tracking accuracy.

- 0.5 extent: marker watershed of negative rain, limited to finite rain >=0.5 mm/h.
- 0.1 extent: same seeds/method, limited to finite rain >=0.1 mm/h.
- Eight-neighbor wet connectivity, all seed pixels as markers, no distance cap.
- Seed labels remain unchanged. Seeded wet-component support must equal the
  partition support. Coreless weak components remain unassigned.
- A radius-9 grouped seed can contain disconnected pieces; one label may own
  several disconnected extent pieces. A wet component may contain several seeds.

The shared `expand_seeded_envelope` helper avoids rerunning identification for
each threshold. `identify_envelope` still supplies its original seed detection
and delegates expansion; production identification/tracking defaults are unchanged.
The new script computes one seed cube per bounded chunk, then performs both
extent calculations frame by frame. `--workers` parallelizes seed replay only;
it does not promise parallel watershed execution or tracking speedup.

## Run on prepared rates

Use an A_1mm directory generated by `compare_rain_thresholds.py`, with its parent
`configuration.json`. Other stream/configuration formats are not silently adapted.
The input must be the **same complete prepared hourly rate cube and metadata**,
not cumulative RAINNC or a differently cropped/subsetted cube.

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
python -u scripts/compare_frozen_extents.py \
  results/local_1996_june72_input_run1/rain_mm_h.npy \
  --metadata results/local_1996_june72_input_run1/input_metadata.json \
  --reference results/threshold_paired_june72_run1/A_1mm \
  --units mm/h --workers 8 --chunk-frames 6 \
  --output-dir results/frozen_extents_june72_run1
```

Choose a new output directory for each run. Existing output is never overwritten.
There is no partial-run resume. `--no-plots` skips figures. Progress reports the
fraction of hours audited; 100% processing is not success until final checks and
reports complete. `SUCCESS` certifies requested invariants, not scientific promotion.

## Outputs and interpretation

| Output | Interpretation |
|---|---|
| `configuration.json` | Source/input/metadata hashes, reference file manifest, settings and versions |
| `frame_accounting.csv` | Eligible, assigned, unassigned rain/pixels and weak-component counts per threshold |
| `extent_objects.csv` | Immutable frame/seed/node/branch mapping, extent size/rain, centroid drift and distance diagnostic |
| `weak_bridge_components.csv` | Wet components containing multiple seeds; not a replacement system graph |
| `support_changes.csv` | Added support and changed ownership of previously assigned pixels |
| `seed_frame_hashes.json` | Exact replay hashes checked against A |
| `extreme_objects.json` | Ten largest area ratios, centroid drifts and any-seed distances across both thresholds |
| `extent_*.png` | Four temporal samples plus frames with the largest recorded extremes |
| `summary.json`, `REPORT.md`, `SUCCESS` | Aggregates, invariant results, limitations and completion marker |

Lowering the threshold must not lose assigned support or change seed labels.
The test also measures ownership differences on previously assigned pixels;
seed-ID equality alone is not used as evidence of extent equivalence. In the
June 72-hour experiment, no such reassignment occurred. Added support includes
both new <0.5 rain and previously unseeded >=0.5 rain reached through weaker bridges.

When old C accounting/geometry files exist, the 0.5 results must reproduce them.
The old experiment did not save C raster hashes, so this check does not assert
pixelwise equivalence of unavailable old C rasters.

Rain accounting uses equal-grid-cell sums over supplied RAINNC only, not
projection-area-corrected volume or any unavailable RAINC. All distance metrics
are grid-cell Euclidean distances to **any** seed pixel, not own-seed distances,
wet-path lengths or physical motion. Centroid drift is a measurement sensitivity;
expanded centroids never feed the tracker. Weak-only lifecycle stages remain
outside A's graph. Extent coverage and longer-looking rain bands are not truth.

## Promotion gate

Inspect extremes, unassigned weak rain, multicore components and ownership changes.
Do not select a threshold only by rain recovery. Keep the June development window
separate from independently chosen evaluation dates. Stronger-seed thresholds,
minimum core area/duration, distance caps, weak-stage temporal attachment and
system-level identity are separate future experiments, not enabled by this test.
